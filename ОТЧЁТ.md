## 2. Использование ИИ (Claude) для создания и оптимизации кода

Инструмент: **Claude (Anthropic)** в среде Claude Code.

### Что было автоматизировано:

#### 2.1 Генерация CSS-архитектуры
Claude сгенерировал всю структуру `style.css`:
- Систему CSS-переменных (`--c-primary`, `--font`, `--shadow`, `--section-v` и т.д.)
- Grid-лейаут для секции Features (`flow-grid` — 3 колонки × 3 строки)
- Адаптивные `clamp()`-значения для всех шрифтов, отступов, размеров изображений
- Анимации появления карточек через `IntersectionObserver` (классы `is-visible`)
- Sticky header с CSS-классом `.scrolled` и плавным переходом тени

#### 2.2 Генерация JS-логики
Claude написал `script.js`:
- **Бургер-меню** с управлением `aria-expanded` и блокировкой скролла body
- **Sticky header** через `scroll` + `classList.toggle('scrolled', scrollY > 10)`
- **FAQ-аккордеон** с закрытием предыдущего открытого элемента
- **Плавный скролл** к якорям для старых браузеров (полифилл)
- **Scroll-reveal** через `IntersectionObserver` с threshold 0.1
- **Валидация формы** (имя, телефон, email, чекбокс согласия) с inline-ошибками
- **Телефонная маска** в формате `+7 (XXX) XXX-XX-XX`
- **Кнопка «наверх»** — появляется при scrollY > 400

#### 2.3 Смена логотипа при скролле
Claude реализовал двойной логотип (светлый/тёмный) без JS:
```html
<img class="logo__img logo__img--light" ...>  <!-- белый, для синего хедера -->
<img class="logo__img logo__img--dark"  ...>  <!-- чёрный, для белого хедера -->
```
```css
.logo__img--dark                        { display: none; }
.site-header.scrolled .logo__img--light { display: none; }
.site-header.scrolled .logo__img--dark  { display: block; }
```

#### 2.4 Hero-секция с градиентом и полупрозрачным фоном
Claude правильно выстроил z-index стопку:
1. `img_horiz_3.png` (сустав) — `z-index: 0`, `opacity: 0.30`, `object-fit: cover`
2. `::after` на `.hero__deco` — градиент `#2F9DCF → transparent` слева направо, `z-index: 1`
3. `.hero__content` — текст, `z-index: 2`
4. `.hero__jar-wrap` — банка, `z-index: 3`

#### 2.5 Работа с Figma-ресурсами
Claude разобрал бинарный `.fig`-файл как ZIP, нашёл все растровые изображения по хешам и скопировал их в проект с понятными именами (`img_jar.png`, `img_scoop.png`, `img_horiz_3.png` и т.д.).

#### 2.6 Ингредиенты — фото с прозрачным фоном
Для изображения ложки на чёрном фоне Claude применил:
```css
mix-blend-mode: screen;
filter: brightness(1.08) contrast(1.05);
```
Это убирает чёрный фон без Photoshop — чёрный цвет в режиме `screen` становится прозрачным.

## 3. Подготовка к интеграции на Bitrix

Полноценный запуск 1С-Bitrix в рамках данного задания не производился. Вместо этого проект структурирован по стандарту Bitrix-шаблона — так, чтобы его можно было подключить к рабочей Bitrix-установке без переработки кода.

### Что сделано:

Все статические ресурсы вынесены в канонический путь Bitrix-шаблона:

```
joint-complex/
├── index.html                            ← лендинг (входная точка)
└── bitrix/
    └── templates/
        └── joint/                        ← шаблон с именем «joint»
            ├── header.php                ← шапка в Bitrix-формате
            ├── footer.php                ← подвал в Bitrix-формате
            ├── .parameters.php           ← параметры шаблона
            ├── css/style.css             ← все стили
            ├── js/script.js              ← вся JS-логика
            └── images/                   ← все изображения из Figma
```

Файлы `header.php` и `footer.php` содержат стандартные Bitrix-вызовы (`$APPLICATION->ShowHead()`, `$APPLICATION->ShowTitle()` и т.д.), `.parameters.php` объявляет доступные регионы шаблона.

### Что потребуется для полного запуска на Bitrix:

1. Установить 1С-Bitrix на сервер с PHP + MySQL
2. Скопировать папку `bitrix/templates/joint/` в аналогичный путь на сервере
3. В административной панели выбрать шаблон `joint`
4. Подключить форму обратной связи через стандартный компонент `bitrix:form.result.new`
5. Контент секций перенести в инфоблоки или Landing Pages

## 4. Оптимизация страницы

### 4.1 Скорость загрузки

| Оптимизация | Реализация |
|------------|------------|
| **Lazy Loading** | `loading="lazy"` на всех изображениях ниже первого экрана (8 штук) |
| **Fetch Priority** | `fetchpriority="high"` на критичных изображениях первого экрана (логотипы, банка, фон hero) |
| **Preconnect** | `<link rel="preconnect" href="https://fonts.googleapis.com">` и `fonts.gstatic.com` — устраняет DNS-lookup задержку для шрифта Onest |
| **Пассивные слушатели** | `{ passive: true }` у scroll-обработчиков — не блокируют рендеринг |
| **IIFE в JS** | `(function(){ ... })()` — исключает загрязнение глобального пространства имён |
| **SVG иконки** | Все иконки инлайн SVG — нет отдельных HTTP-запросов |
| **CSS-переменные** | Централизованные токены, нет дублирования значений |

### 4.2 SEO-параметры

| Параметр | Значение |
|---------|---------|
| `<title>` | «Complex SW СУСТАВЫ — FMF \| Порошок для суставов» |
| `<meta name="description">` | 160 символов с ключевыми словами |
| `<meta name="keywords">` | Целевые ключи: суставы, глюкозамин, хондроитин и т.д. |
| Open Graph | `og:title`, `og:description`, `og:image`, `og:locale` |
| `lang="ru"` | На теге `<html>` |
| `aria-label`, `aria-expanded`, `role` | На интерактивных элементах |
| Семантика | `<header>`, `<nav>`, `<section>`, `<footer>`, `<h1>`→`<h2>`→`<h3>` иерархия |
| Якорная навигация | `id` на всех секциях, `href="#section"` в меню |

### 4.3 Адаптивность

- Весь лейаут на CSS Grid и Flexbox
- Все размеры через `clamp(min, vw, max)` — плавное масштабирование
- Media queries: `@media (max-width: 768px)` для мобильного меню, переключения на колонку
- Бургер-меню для мобильных с блокировкой прокрутки body
- `scroll-padding-top` учитывает высоту sticky-хедера
- Проверено: нет горизонтального скролла на 375px (мобильный)
